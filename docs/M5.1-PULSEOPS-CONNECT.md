# M5.1 — PulseOps Connect

## Goal
Accept operational CSV exports, validate row-level data quality, normalize them into the OIE canonical model, and preserve the existing OIE analysis flow.

## Required CSV files
- `equipment.csv`
- `availability.csv`
- `appointments.csv`
- `executions.csv`

## Endpoint
`POST /v1/datasets/csv-bundle?organization_id=<id>` as multipart/form-data with fields `equipment`, `availability`, `appointments`, `executions`.

## Data quality contract
The endpoint returns a canonical dataset record and a quality report with received, valid and rejected row counts plus row-level issues. Cross-file referential integrity failures are rejected with HTTP 422.

## Engineering constraints
- UTF-8/UTF-8-BOM only in M5.1.
- No patient PII is required by the current Capacity use case.
- Canonical JSON remains the storage/reproducibility boundary for OIE.
- The OIE core stays independent of FastAPI, SQLAlchemy and file formats.
